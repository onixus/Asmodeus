## Эксплуатационный контракт аудита

При `ASMODEUS_AUDIT_LOG` обязателен `ASMODEUS_AUDIT_SIGNING_KEY`: путь к
64-байтовому Ed25519 secret key в hex-формате CLI `keygen`. Ключ должен переживать
рестарты и храниться отдельно от каталога сценариев. Без файлового журнала
допускается временный ключ для локальной симуляции. Ключ аудита используется
также для подписи lifecycle webhooks.

Журнал содержит все записанные ревизии. API `/runs` и экспорт возвращают
актуальную ревизию каждого run; порядок — первое появление run. Старый JSONL
с одной записью на run совместим по формату, но нужен исходный доверенный ключ.
Старые demo-журналы с утраченным временным ключом нельзя объявлять доверенными:
их следует сохранить отдельно и явно выбрать новый журнал/ключ. Автоматической
переподписи или удаления старых данных нет. Ротация ключей и проверка цепочки
всех исторических ревизий не реализованы; startup проверяет актуальные записи.

Хранилище рассчитано на **один процесс control-plane на один файл**. Mutex
сериализует клоны одного `AuditStore`, но не разные процессы. Это не HA-БД.
При аварийном завершении во время записи может остаться неполная последняя
строка: следующий запуск выдаст ошибку, а не отбросит историю. `sync_all`
применяется к файлу; гарантия сохранения новой directory entry при потере
питания отдельно не заявляется. Для большого журнала нужны retention,
индексы/пагинация и отдельное хранилище, поскольку актуальные записи находятся
в памяти и поиск по ID линейный.

Допуск `QUEUED` сохраняется до инъекции; терминальный результат — после неё.
Ошибка финальной записи аудита не означает, что сценарий не выполнялся.
Автоматически повторять такой запрос нельзя: idempotency keys ещё не реализованы.
После рестарта незавершённый run становится `INTERRUPTED` без повторного запуска.
Таймаут gRPC также **не доказывает отмену или rollback** на удалённом runner.

## Состояние после завершения функций

Подробный контракт: [features-2026-09-22.ru.md](features-2026-09-22.ru.md).
Закрыты trust pinning сценариев, подписанный execution plan, remote cancel,
lease/deadline, blocking worker, один активный run, отдельные песочницы,
подтверждение cleanup и происхождение метрик. Кампании/расписания сохраняются
в snapshots; незавершённые audit runs восстанавливаются как `INTERRUPTED`.

## Незакрытые ограничения

| Приоритет | Подтверждённое ограничение | Что требуется |
| --- | --- | --- |
| P0 для общего недоверенного хоста | Path checks не заменяют descriptor-relative операции; нет namespaces/cgroups и восстановления cleanup после SIGKILL runner | Защищённый от чужой записи canary-root; отдельный Linux этап изоляции/восстановления |
| P1 | Каталог подписывает доверенные локальные файлы; нет внешнего approval/signing pipeline | Контроль доступа к каталогу и ключу, workflow поставки сценариев |
| P1 | JWT tenant/permissions не разделяют глобальное состояние | Tenant isolation до multi-tenant deployment |
| P1 | Webhooks best-effort, registry временный, нет idempotency key и HA | Outbox, идемпотентность и транзакционное хранилище при масштабировании |
| P1 | Кампания — синхронная цепочка отдельных runs | Durable campaign workflow для resume/background целой цепочки |
| P2 | Linux eBPF attach — заглушка; ClickHouse только экспорт; feedback заявлен отправителем | Linux/CAP_BPF acceptance, доставка телеметрии и аттестация внешних датчиков |
